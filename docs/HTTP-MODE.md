# Общий HTTP-режим: один коннектор на много пользователей

Обычный режим (`1c-odata-mcp`, stdio) — один пользователь, базы в `.env` или файле баз. Общий HTTP-режим
(`1c-odata-mcp-http`, `src/http.ts`) нужен сервису, где **каждый пользователь подключает свою базу 1С**, а коннектор
один на всех: базы не настраиваются заранее, учётка приходит с каждым запросом.

```
сервис (бэкенд чата) ──POST /mcp, Bearer + X-OneC-Connection──► коннектор ──HTTPS/OData──► 1С пользователя
```

## Запуск

```bash
docker build -t 1c-odata-mcp-http .
docker run -d --name onec-connector -e MCP_HTTP_TOKEN=<случайная строка ≥ 24 символов> \
  -v onec_data:/data 1c-odata-mcp-http
```

Порт наружу не публикуйте: коннектор должен быть доступен только сервису (внутренняя сеть Docker).

| Переменная | По умолчанию в образе | Смысл |
|---|---|---|
| `MCP_HTTP_TOKEN` | — (обязательна) | Общий ключ: запрос без `Authorization: Bearer <ключ>` — 401 |
| `PORT` | `8080` | Порт HTTP |
| `READ_ONLY` | `true` | Запрет записи для всех баз; запись включается только явно `READ_ONLY=false` |
| `ODATA_HTTP_WRITE_TOOLS` | — (пусто) | Пишущие инструменты общего режима через запятую, напр. `write.sales.quick_invoice,write.sales.quick_sale`; пусто — ни одного |
| `ODATA_RETRIES` | `1` | Повторы запросов к 1С при сбоях |
| `ODATA_WRITE_JOURNAL_DIR`, `ODATA_CACHE_DIR` | `/data/…` | Журнал записи и кеш `$metadata` — на томе `/data` |
| `MCP_LOG_STDERR` | `1` | Логи в stderr (`docker logs`), а не в файл, как под stdio-клиентом |

Остальные `ODATA_*` (таймаут, размер страницы, лимиты строк) — как в `.env.example`. Переменные баз
(`ODATA_BASE_URL`, `ODATA_DB_*`, `ODATA_CONFIG`) в этом режиме не читаются.

## Запрос

`POST /mcp` — Streamable HTTP без сессий (каждый запрос самостоятелен; `GET`/`DELETE` — 405). Заголовки:

- `Authorization: Bearer <MCP_HTTP_TOKEN>`;
- `X-OneC-Connection: <base64url(JSON)>`, где JSON:

```json
{ "id": "3f2c…", "baseUrl": "https://…/odata/standard.odata/", "username": "odata", "password": "…",
  "writable": false, "label": "ТОО «Ромашка»" }
```

`id` — идентификатор подключения в сервисе (латиница, цифры, `-`, `_`): из него имя базы `c_<id>` — параметр
`database` инструментов и папка журнала записи. Запись возможна, только если `writable: true` **и** `READ_ONLY=false`;
пишущие инструменты, как и в обычном режиме, сначала дают предпросмотр, а пишут при `confirm=true` с `operationId`.

`GET /healthz` — `{ "ok": true, "version": "…" }` без авторизации.

## Чем отличается от обычного режима

- **Нет** шлюза `meta.list_tools` / `meta.call_tool` (инструменты для модели отбирает сервис). Печатные формы
  `read.document.print_*` и вложения `read.files.*` разрешены: PDF и файлы отдаются ресурсом MCP, на диск коннектора
  при `printToDisk=false` ничего не пишется; быстрые инструменты (`quick_invoice`, `quick_sale`, `quick_reconciliation`)
  при создании печатают PDF ресурсом в ответе записи (без диска). Вложения в общем режиме — не больше 10 МБ.
- **Запись** — только инструменты из `ODATA_HTTP_WRITE_TOOLS` (и `write.operation.status` вместе с ними), при
  `READ_ONLY=false` и `writable: true` у подключения.
- **Сеть:** адрес базы присылает пользователь, поэтому запросы к 1С не уходят во внутренние и служебные сети
  (`10/8`, `172.16/12`, `192.168/16`, `127/8`, `169.254/16`, `100.64/10`, IPv6-локальные) — проверяются все адреса из
  DNS в момент соединения; перенаправления (3xx) запрещены — укажите точный адрес OData.
- **Пул подключений:** подключение (с его кешами `$metadata`, плана счетов, субконто) переиспользуется между запросами,
  пока учётка та же; сменились адрес, логин, пароль или право записи — новое подключение. Не больше 4 одновременных
  запросов к одной базе, простаивающие подключения освобождаются через 30 минут.
- **Логи** без пароля, `Authorization` и `X-OneC-Connection`.
